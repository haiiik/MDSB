## 先说替换：不是缺功能，是入口问题

代码里确实有替换（`components/SearchBar.vue:119` 那一行 `v-if="canReplace && search.withReplace"`，
`state/search.ts:47` 注释写明「替换区是否展开（`Ctrl+H` 才展开，`Ctrl+F` 只看）」）。
所以两条快捷键打开的是**同一条工具条**，差别只在替换那一行出不出现——这就是她觉得
「和 Ctrl+F 长得一样」的原因。另外**阅读模式** `canReplace=false`（`kernel/searchDom.ts:59`，只读档），
那条模式下永远不会有替换行，这是既定口径不是 bug。

改法（她的话：「把 `Ctrl+F` 的工具条中加上替换得了」）：工具条右侧加一颗「替换」展开按钮，
`canReplace` 为真时常驻可见；`Ctrl+H` 保留为「打开并直接展开」的快捷路径。
**代价：1 颗（约半天）**，含 e2e 补两条（按钮展开/收起、展开后替换可用）与一条反向判据
（阅读模式不出现这颗按钮）。

## 工单拆分与建议顺序

**M3-131 查找条内联替换入口** — 1 颗 / 0.5 天。最便宜、立刻看得见，先做。

**M3-132 i18n 基座（不含翻译）** — 2 颗 / 2~3 天。抽文案、建消息目录（自己写一个约 200 行的字典，
不引 vue-i18n，少一个依赖）、语言切换入口与持久化。
**这颗必须排在其它功能之前**：现在约 263 条端到端 + 151 条桌面断言是按中文文本押的
（「未打开文档」「保存并命名」「源码模式改过内容，编辑模式的撤销栈已重新开始」…），
每加一个新功能就多一批中文断言要迁。**基座里同时把判据从「按中文文本押」改成「按 testid 押」**，
这件事越早做越便宜，也顺手让测试更稳。

**M3-133 英文文案** — 1~2 颗 / 1~2 天。逐组件填 en 字典；中英混排的字族回退；
英文变长后侧栏页签、工具栏按钮、底栏各项的宽度重排（129 刚把顶栏收到 32px，英文标签可能顶回来，
要按有效 CSS 像素重新量）。前置决定：默认语言跟系统还是固定中文？（我倾向**默认中文 + 设置里可切**，
不猜她的环境）

**M3-134 脚注** — 2 颗 / 2~3 天。`remark-gfm` 的 footnote 扩展（不引新解析器）→
schema 加 `footnote_reference` / 文末 `footnote_definition` → mdast↔PM 双向映射携带源区间 →
阅读模式渲染上标与回跳 → 编辑模式「点引用跳到定义改文字」（复用 Mermaid 的倒查与就地编辑）。
**一条口径要先定**：新增/删除脚注会让编号**跨块重排**，这与「块外逐字节不动」直接冲突。
我的默认做法：**只在被编辑的那个脚注块内重排，其它脚注定义块不动**（宁可编号暂时不连续，
也不悄悄改用户没碰的段落）。保真矩阵补两行钉住它。

**M3-135 插入文档链接（她说的「目录文件」）** — 3~4 颗 / 4~6 天。
弹层：按文件名搜索工作区内的 `.md`、显示它相对根目录的路径、选相对/绝对路径
（当前文件未保存、没有基准目录时**相对路径禁用**），确认后组装 `[文件名](路径)` 插到光标处。
真正的工作量在**宿主层要加两个新原语**：列目录（递归扫工作区、跳过 `node_modules`/隐藏目录、
大目录要有上限与懒加载）与「工作区根目录」这个概念本身（现在只有「当前文件所在目录」，
没有根；得先定根是什么——最近一次打开文件的公共祖先？还是设置里指定？）。
按硬约束 4，**每个新原语都要同步补浏览器 mock 实现**，否则这条功能在端到端里结构性不可测。
路径换算（相对路径里的空格、`..`、Windows 反斜杠 → URL 正斜杠）单独钉一组单测。

**M3-136 公式块（KaTeX）** — 3 颗 / 3~5 天。`remark-math` + `rehype-katex`（KaTeX 的 CSS 与字体打进包，
**不联网**，产物约 +300KB）→ schema 加 `math`（块级）与 `math_inline`（行内）→
阅读模式渲染；编辑模式按她的话**复用 Mermaid 那套**：NodeView 里显示渲染结果，
双击切到源码就地编辑，失焦/回车提交，一次 `Ctrl+Z` 退回。
风险：`\` 与 `{}` 在 Markdown 里和转义规则打架，边界情况多；行内公式与粗体/代码 mark 混排时
映射层要单独处理（106 那两条「混合 mark」的教训适用）。

## 她第二轮回话（2026-10-17）

- **i18n 默认语言（她第二轮改口，以此为准）**：**安装时选**——安装器读当前系统语言作为预选；
  读不到就**不给默认值，必须选一项才能继续安装**；设置里可切，**只有两个选项：中文 / English**（设置里不做「跟随系统」）。
  落地口径（**这条会加到安装器上，132 之后另开一颗工单**）：NSIS 加一页自定义语言选择（nsDialogs 两颗单选），
  预选值取 `kernel32::GetUserDefaultUILanguage`（0x804 等中文系 → 中文，其它已知 → English，取不到/未知 → 无选中）；
  未选中时拦住「下一步」并提示必须选。装完写 `HKCU\Software\MDStar\Language = zh|en`，
  Go 侧首启若设置里没有语言项就读这个值（读不到再回落 `navigator.language`），**之后以设置为准**。
- **README 要有英文版**：`README.md`（中文，现状）+ `README.en.md`（英文），两份互相在顶部给链接。
  截图沿用同一批（界面文案是中文，英文 README 里注明「截图为中文界面」）。
- **「目录文件」重命名**：按真实功能叫 **插入文档链接**（英文 `Insert Document Link`），
  入口在编辑档工具栏与右键菜单，弹层标题「从工作区选择文档」。
- **工作区根目录**：她问「为什么要定」→ 结论是**不必新增概念**：
  把「工作区」定义成**当前文件所在目录**，搜索=该目录递归，相对路径=相对当前文件所在目录
  （未保存的文档没有基准目录 → 相对路径禁用，与她说的规则一致）。
  这样少一个设置项、少一套"根"的推断逻辑。若以后要做真正的多目录知识库，再单开一颗工单引入「工作区」。
